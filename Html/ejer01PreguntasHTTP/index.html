Sección de Preguntas sobre HTTP

  1. Pregunta 1: ¿Sobre qué protocolo binario está montado HTTP?
    Respuesta: HTTP se monta sobre TCP/IP (TCP como protocolo de transporte). Con HTTP/2 y HTTP/3, HTTP/3 corre sobre QUIC (que a su vez va sobre UDP).
  2. Pregunta 2: ¿Cuáles son los clientes y servidores HTTP más utilizados?
    Respuesta: Clientes: navegadores (Chrome, Firefox, Safari, Edge), curl, Postman. Servidores: Apache HTTP Server, Nginx, Microsoft IIS, y a nivel de aplicación Node.js/Express, Tomcat.
  3. Pregunta 3: ¿Qué verbos admite un comando en el requerimiento HTTP?
    Respuesta: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, TRACE y CONNECT.
  4. Pregunta 4: ¿Qué contenido lleva el body de un requerimiento HTTP?
    Respuesta: Los datos enviados al servidor: formularios, JSON, XML, archivos binarios, etc. No todos los métodos lo usan (GET normalmente no lleva body).
  5. Pregunta 5: ¿Qué diferencia existe entre URL y URI?
    Respuesta: URI es el concepto general: identifica un recurso (puede ser por nombre -URN- o por ubicación -URL-). URL es un tipo de URI que además indica cómo acceder al recurso (protocolo, dominio, ruta).
  6. Pregunta 6: ¿Cómo se almacena información relacionada con las respuestas HTTP?
    Respuesta: A través de cookies, cache del navegador (headers como Cache-Control, ETag, Expires) y en el local storage/session storage del cliente.
  7. Pregunta 7: ¿Qué significa HTTP sobre conexiones preexistentes?
    Respuesta: Es el uso de "keep-alive" (persistent connections): reutilizar la misma conexión TCP para múltiples requests/responses, evitando el costo de abrir una nueva conexión cada vez.
  8. Pregunta 8: ¿Qué significa Virtual Hosting?
    Respuesta: Es la capacidad de un mismo servidor físico de alojar múltiples sitios/dominios distintos, diferenciándolos por el header Host de la request.
  9. Pregunta 9: ¿Qué significa Cache por ETag?
    Respuesta: El servidor asigna un identificador (hash) al recurso. El cliente lo guarda y en próximos requests lo envía (If-None-Match); si no cambió, el servidor responde 304 Not Modified sin reenviar el contenido.
  10. Pregunta 10: ¿Por qué HTTP se considera STATELESS?
    Respuesta: Porque cada request es independiente: el servidor no guarda información de requests anteriores. Cada petición debe contener todo lo necesario para ser procesada (el estado se maneja aparte, vía cookies, sesiones o tokens).
  11. Pregunta 11: ¿Qué nueva versión de HTTP se usa para mejorar la velocidad de la web?
    Respuesta: HTTP/2 (multiplexación, compresión de headers) y más recientemente HTTP/3, que usa QUIC.
  12. Pregunta 12: ¿Cómo mejora el comportamiento en ambientes ruidosos o de conexión débil?
    Respuesta: HTTP/3 sobre QUIC evita el "head-of-line blocking" de TCP: si se pierde un paquete, no bloquea todas las demás transmisiones, y además reduce la latencia de reconexión, lo que mejora mucho la experiencia en redes inestables (móviles, wifi débil).
