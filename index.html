Protocolo HTTP

Preguntas

  1. ¿Sobre qué protocolo binario está montado HTTP?
    HTTP se monta sobre TCP/IP. Con HTTP/3 corre sobre QUIC, que a su vez va sobre UDP.
  2. ¿Cuáles son los clientes y servidores HTTP más utilizados?
    Clientes: navegadores (Chrome, Firefox, Safari, Edge), curl, Postman. Servidores: Apache, Nginx, IIS, Node.js/Express, Tomcat.
  3. ¿Qué verbos admite un comando en el requerimiento HTTP?
    GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, TRACE y CONNECT.
  4. ¿Qué contenido lleva el body de un requerimiento HTTP?
    Datos enviados al servidor: formularios, JSON, XML, archivos binarios, etc. GET normalmente no lleva body.
  5. ¿Qué diferencia existe entre URL y URI?
    URI es el concepto general que identifica un recurso. URL es un tipo de URI que además indica cómo acceder a él (protocolo, dominio, ruta).
  6. ¿Cómo se almacena información relacionada con las respuestas HTTP?
    A través de cookies, cache del navegador (Cache-Control, ETag, Expires) y local/session storage.
  7. ¿Qué significa HTTP sobre conexiones preexistentes?
    Es el uso de keep-alive: reutilizar la misma conexión TCP para varios requests/responses.
  8. ¿Qué significa Virtual Hosting?
    Un mismo servidor físico aloja múltiples sitios/dominios, diferenciados por el header Host de la request.
  9. ¿Qué significa Cache por ETag?
    El servidor asigna un identificador al recurso; el cliente lo envía en If-None-Match, y si no cambió responde 304 Not Modified.
  10. ¿Por qué HTTP se considera STATELESS?
    Porque cada request es independiente: el servidor no guarda información de requests anteriores.
  11. ¿Qué nueva versión de HTTP se usa para mejorar la velocidad de la web?
    HTTP/2 (multiplexación, compresión de headers) y HTTP/3, que usa QUIC.
  12. ¿Cómo mejora el comportamiento en ambientes ruidosos o de conexión débil?
    HTTP/3 sobre QUIC evita el head-of-line blocking de TCP y reduce la latencia de reconexión.
